Сигналов в них нет, список файлов виден в поле `paths.scanned` отчета. Ограничение охвата: правила не отслеживают поток данных, тесты, скрипты и документация в область не входят.
- Воспроизведение: из корня репозитория `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\scan-sast.ps1 -Label before`. Сканер завершился с кодом 0, раздел `errors` в отчете пустой. Нулевой код означает, что сканирование завершилось, а не отсутствие дефектов.
- Первичный результат: `docs/s09/raw/semgrep-before.json`, 8 сигналов на трех файлах.
- Сигнал: `sql-commandtext-concat` (ERROR) и `sql-commandtext-assignment` (WARNING), оба на `src/NotesApi/NotesRepository.cs:48`, см запись реестра F-01.
- Интерпретация: значение `q` приходит из query string маршрута `GET /notes/search` (`src/NotesApi/Program.cs:16`), значение `owner` из заголовка `X-User` там же, оба попадают в текст запроса конкатенацией. Нарушается конфиденциальность заметок: payload `%' OR 1=1 -- ` закрывает строковый литерал и снимает условие по владельцу. Сигнал широкого правила на той же строке указывает на ту же причину и отдельным дефектом не считается.
- Решение: подтвержден, приоритет высокий. Действие это передать пользовательские значения как данные, а не как часть текста запроса, структура запроса должна задаваться только кодом.
- Изменение или отклонение: `src/NotesApi/NotesRepository.cs`, метод `Search`. Текст запроса стал постоянным, `owner` и шаблон `LIKE` передаются именованными параметрами `$owner` и `$pattern` через `AddWithValue`. Штатный поиск по подстроке сохранен. Остаточный риск: подстановочные символы `%` и `_` внутри `q` продолжают работать как шаблон `LIKE`, это расширяет выборку в пределах заметок самого владельца и не позволяет выйти за условие `owner`.
- Объект после: тот же commit `1802bbf` плюс незакоммиченные изменения. `git status --short`: `M src/NotesApi/NotesRepository.cs`, `M tests/NotesApi.Tests/NotesTests.cs`, `?? docs/`, `?? s09-fix.patch`. 2. Ручная проверка на той же версии до изменения. Приложение запущено командой `dotnet run --project src/NotesApi --urls http://localhost:8080`. Запрос `GET /notes/search?q=%' OR 1=1 -- ` с заголовком `X-User: alice` вернул 200 и две записи, вторая с `owner: bob`. Штатный запрос `GET /notes/search?q=note` с тем же заголовком вернул одну запись `owner: alice`. Те дефект воспроизводится через публичный маршрут, а не только в тесте.
